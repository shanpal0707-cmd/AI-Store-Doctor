AI Store Doctor

Architecture Analysis · Current State & Recommended Backend Plan

1 · PROJECT ARCHITECTURE

Current Structure

A standalone Angular 22 single-page application. No backend, no services layer — all logic lives directly in components.

Framework

  • Angular 22 (standalone components)
  • No NgModules — fully component-driven
  • Angular Router for page navigation
  • FormsModule for two-way binding
  • CommonModule for *ngIf / *ngFor

Pages / Routes

  • / — Landing / Home page
  • /store-setup — Store onboarding
  • /dashboard — Store overview
  • /products — Product Doctor
  • /ai-analysis — AI Analysis

State & Storage

  • Zero Angular services — no shared state
  • All data stored in localStorage
  • storeData key → store profile
  • products key → product array
  • Each component reads localStorage independently

No Backend

  • No HTTP client configured
  • No API services or interceptors
  • No environment files
  • No server-side AI calls
  • Analysis is pure client-side JavaScript
2 · FRONTEND DATA FLOW

How data moves today

Store Setup → Dashboard

User fills StoreSetup form
→
localStorage.setItem('storeData')
→
Router navigates to /dashboard
→
Dashboard reads localStorage on ngOnInit

Products Page → AI Analysis

User adds product via form
→
localStorage.setItem('products')
→
AI Analysis reads localStorage on load
→
Client-side JS runs fake "AI"
→
Result shown after setTimeout(1000ms)

No HTTP calls exist anywhere. All computations (profit, sales rate, health score, "AI" recommendation) happen synchronously in the browser.

3 · ALREADY IMPLEMENTED

What is built and working

Landing page — full marketing page with hero, features, how-it-works, contact, CTA, footer
Store Setup form — collects store name, business type, size, primary goal; saves to localStorage
Dashboard — reads store profile, displays health score (hardcoded 78), metric cards, insight list, quick actions
Products page — add / delete products with name, category, cost price, selling price, stock qty, units sold, sales period
Product calculations — profit per unit, sales rate %, health score (0–100), health status label (Healthy / Needs Attention / Critical)
AI Analysis page UI — "Analyze Products with AI" button, loading state, result cards, recommendation area
Client-side mock analysis — counts products needing attention vs healthy; generates a text recommendation string; simulates a 1-second delay
4 · WHAT IS MISSING

Gaps for a real backend-based AI analysis

Area What's missing Impact
Angular HTTP No HttpClient, no provideHttpClient(), no services Cannot make any API calls
Angular Service layer No shared services (ProductService, AnalysisService, StoreService) Components duplicate localStorage logic; no single source of truth
Environment config No environment.ts files; no API base URL defined Cannot switch between dev and production endpoints
Node.js / Express backend No server directory or package at all Nothing to receive product data or call an AI model
AI / LLM integration No API key handling, no OpenAI / IBM Watson / Gemini call Recommendation is a hardcoded string — not real AI
Per-product AI diagnosis AI analysis returns one global recommendation, not per-product insight User cannot act on individual products
Error handling No loading states for async ops, no error UI API failures would be silent
CORS / Proxy No Angular proxy config for dev API calls Browser would block calls to localhost:3000 from localhost:4200
5 · RECOMMENDED BACKEND ARCHITECTURE

Node.js + Express backend

A lightweight Express server that acts as a secure proxy between the Angular app and an AI provider (e.g. OpenAI GPT-4o, IBM Watson, or Google Gemini).

Angular Frontend
  • AnalysisService (HttpClient)
  • POST /api/analyze
  • Renders per-product AI results
→
Express Server
  • POST /api/analyze
  • Validates & sanitizes input
  • Builds AI prompt
  • Calls AI API (server-side)
  • Returns structured JSON
→
AI Provider
  • OpenAI GPT-4o (recommended)
  • API key stored in .env
  • Prompt-engineered for retail

Recommended folder structure — server/

server/
  index.js            ← Express entry point
  routes/
    analyze.js        ← POST /api/analyze route
  services/
    openai.service.js  ← AI prompt builder + API call
  middleware/
    validate.js       ← Input validation
  .env               ← OPENAI_API_KEY (not committed)
  package.json

API Endpoints

POST /api/analyze
Accepts store profile + product array → returns per-product AI diagnosis + overall recommendation
GET /api/health
Simple liveness check — returns { status: "ok" }

Request / Response shape

Request body

{
 "store": { name, type, size, goal },
 "products": [
  { id, name, category,
    costPrice, sellingPrice,
    stockQty, unitsSold,
    salesPeriod }
 ]
}

Response body

{
 "overallScore": 74,
 "summary": "...",
 "products": [
  { id, status, diagnosis,
    action, priority }
 ],
 "topRecommendation": "..."
}
6 · ANGULAR ↔ BACKEND COMMUNICATION

How the Angular frontend should call the backend

Changes needed in Angular

Add provideHttpClient() to app.config.ts
Create src/environments/environment.ts with apiUrl: 'http://localhost:3000'
Create src/app/services/analysis.service.ts — injectable service wrapping HttpClient POST to /api/analyze
Create src/app/services/product.service.ts — single source of truth for reading/writing products (replaces per-component localStorage reads)
Update AiAnalysis component to call AnalysisService.analyze(), handle Observable, show per-product results
Add Angular proxy config (proxy.conf.json) so /api/* calls are forwarded to localhost:3000 during development

Data flow with backend

User clicks "Analyze Products with AI"
↓
AiAnalysis component calls AnalysisService.analyze(store, products)
↓
HttpClient POST → /api/analyze (via proxy → Express)
↓
Express validates input, builds retail-focused AI prompt
↓
OpenAI API call (server-side, API key hidden)
↓
Express parses AI response → returns structured JSON
↓
Angular renders per-product diagnosis + overall recommendation
